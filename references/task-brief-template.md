# Worker 任务书模板

派发每个子 agent 前，按下列模板逐项填写。任务书必须自包含（worker 看不到主对话历史），禁止代词指代上下文。

```
你是多 agent 并行协作中的 worker-<字母/角色名>（<角色定位，如：后端/前端/测试/文档>）。
独立完成以下任务，不要越界。

工作目录（只许在这里写文件）：<绝对路径>

任务：
1. <交付物 1，含技术要求>
2. <交付物 2，含技术要求>
3. <自测要求：必须实际运行的命令，如 python -m unittest / npm test / lint>

验收标准（全部满足才算完成）：
- <可执行检查 1：命令 + 期望结果>
- <可执行检查 2：如"测试全部通过"、"页面无外部 CDN 可离线打开">

边界（违反即失败）：
- 只许写 <目录> 下的文件，禁止修改/创建其它任何目录的内容。
- 禁止 rebase / force-push / 合并到 main / 修改共享依赖版本。
- <任务特有的禁改清单，如：禁止改 tests/、禁止改 package.json>

完成后报告（缺一不可）：
1. 创建/修改的文件清单（绝对路径）
2. 验证结果原文（命令输出的关键行，不是"应该通过"）
3. 一句话总结
```

## 填写要点

- **一包一目录**：任务边界以目录归属表达，先划清再派发；两个包不许共写同一文件。
- **验收可执行**："代码质量好"不是验收标准；`python -m unittest 全绿` 才是。
- **回报格式固定**：统一三段式回报，便于主 agent 集成核对。
- **并行派发**：多个任务书在同一条消息内一起发出（多路 Agent 调用），实现真正并发。
- **接口变更通知**：worker 间确需协调时，约定共享契约文件（如 CONTRACT.md）为唯一事实源，或要求互发消息。
